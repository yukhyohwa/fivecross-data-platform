# chat_bi 全面自检报告（2026-10-15）

> 历史记录，非现行配置：联网搜索整体已按用户要求移除，包括 provider 服务、缓存、工具入口、配额和 UI；下文联网搜索整改建议不再适用。LLM API 调用、token 费用显示、用户数据查询及知识库/SQL 检索保留。旧搜索代码与清单存于 backup/fivecross-data-platform-legacy-knowledge/web-search-removal（更早配额归档位于 search-quota-removal）。

> 审计方式：5 路子系统摸底 → 6 维度审查 → 每条发现双人对抗验证（151 个 agent / 1805 次工具调用，约 33 分钟）。
> 结果：**69 条发现验证通过**（高危 20 / 中 36 / 低 13）+ 10 条盲区补漏。README 按约定留到最后更新（大纲见 §6）。

## 一、结论速览

**1. 目标闭环（AI 生成 → 人工审核 → 对话调用）**：四类能力的 AI 生成入口齐全且有预检；但「人工审核」整体不达标——主聊天管线是「点保存才写入」（达标），而 会话转能力 to-kb、飞书桥 feishu_to_kb/skill、gap_fix applied、订阅保存 四条路径 AI 直写盘无确认；深度分析 agent 每轮还携带 4 个 BI 写工具可直接改看板/报表。已保存能力的调用：专项/SQL/知识库/算法模型可检索命中，但**「指标」没进主对话链路（空转）**，历史报告未按用户隔离。

**2. 空转/可合并**：可删约 4000+ 行死代码（workbench 全链、Sync/ 6 组件、db_service 退役套件等）；vanilla 管理 5 页与 React 工作台重复维护应删；4 个编辑器/3 个 AgentPanel/多处复制壳代码可抽共享组件再减约 1000 行；模块关联有 6 处双向不对齐（后端有前端无 ×3、前端有后端无 ×1、断链 ×3）。

**3. 视觉统一**：三套主色并存（琥珀 #e8a838 / #007bff / #4f7cff）、按钮 4 套规格、图标 emoji 与 lucide 混用、暗色下 reports 页内联亮色成大白块、React 壳无 CJK 字体声明、10-11px 小字号与低对比度多处低于 AA。建议单一 --brand token + 共享 Button 组件收口，分两批落地。

**4. AI 能力**：深度思考只覆盖「深度分析」开关与 SQL 编辑器 AI 侧栏两条路径；主对话 6+ 处 LLM 调用、知识问答、各生成器都是单发无工具、全仓无流式。默认模型还是网关已知被拒的 claude-opus-4-6（每次默认调用白失败一次）。按任务分模型 / temperature 可配等灵活性基本为零。

**5. 联网搜索 MCP**：现状 = 共享单账号 Serper key + 全局事后计数，但「限次」实际不存在（无配额、无超限拦截，且唯一调用点从未触发过）；计数接口无鉴权、前端把全局次数展示成个人用量。**推荐方案 A：继续共享 + per-user 配额闸门 + 接入深度分析 agent**（详见 §7）。

**6. README**：新增章节大纲已备好（§6），等整改落地后最后更新。
