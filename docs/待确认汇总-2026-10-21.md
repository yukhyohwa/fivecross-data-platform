### 决策 3 说明：auto_extract 是否接线

- **auto_extract 是什么**：代码里早已存在的一个「对话后自动提取记忆」函数（`memory_manager.auto_extract`）：对话结束后后台调一次 LLM，从「你问的问题 + AI 的回答」里抽取值得记住的知识点，自动存成记忆。
- **「是否接线」的意思**：这个函数写好后从未被挂到任何对话流程上（全库搜不到调用方，是死代码）。接线 = 让每次深度分析对话结束后自动跑它。
- **两种选择**：
  - **不接线（我建议）**：记忆靠深度分析 agent 在对话内按「记忆沉淀规则」主动生成（已实施的方式）。优点：不额外多一次 LLM 调用（省钱省延迟）、agent 自己判定类型/绑定更可控。缺点：agent 忘了沉淀就没了。
  - **接线**：对话后自动再提取一次。优点：兜底，agent 没沉淀的也能捞回来。缺点：每次对话多一次 LLM 调用（费用+延迟）、可能与 agent 已沉淀的记忆重复（虽然有相似度去重）、提取质量依赖这个单独的小提示词。
- 拍板「不接线」的话，我会把这段死代码删掉；拍板「接线」的话，挂在深度分析对话结束处，并加去重。

### 决策 5 说明：手动新建/编辑时选类型/绑定

- **现状**：记忆管理页（个人定制 →「个人记忆」）新建/编辑弹窗里只有内容文本框。类型（日常/专项/SQL/知识库/算法）和绑定资产名只能由深度分析 agent 在对话中自动打标，用户无法手动指定或修正。
- **要做的**：在新建/编辑弹窗里加两个下拉框——「类型」下拉（5 选 1）+「绑定资产」下拉（列出你的专项/SQL/知识库文档/算法名，选「日常」时禁用）。新建时选好一起保存；编辑时改类型/绑定随内容一起提交。
- **意义**：agent 打错标可以手动修正；也可以不经过对话、手动建一条「绑定了某个专项」的记忆（下次问到这个专项就会自动召回这条）。
- 改动范围：前端 MemoryPage 弹窗 + 编辑时把 mem_type/bind_name 传给 PUT（后端已支持，零改动）。
