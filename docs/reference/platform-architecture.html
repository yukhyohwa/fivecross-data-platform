Data AI · 功能与运行逻辑说明

用自然语言提问，自动取数、出图，并生成带归因与预测的分析报告

Data AI 是「数据分析agent搭建工具」中的对话式数据分析工具：用户用一句话提问，系统自动匹配或生成 SQL、在数据仓库上取数、按 SQL 头部注释出图，再经「生成 → 验证 → 汇总」三模型交叉验证，产出可直接使用的专项报告。

后端 FastAPI 前端 原生 JS + ECharts 数据 StarRocks / MySQL 大模型 内部 LiteLLM 网关 流式 SSE

01概览

数据分析agent搭建工具是一个 FastAPI 应用（默认端口 8000），承载完整个人数据工作台：Data AI（对话取数 / 专项 / 知识库 / SQL / 算法模型 / 指标 / 订阅报告 / 记忆 / 权限，根路径 /api/*）。飞书文档子应用已在物理合并时独立出去，不再挂载。

模块作用技术
前端对话页、专项页、知识库、模型、报告、SQL 编辑器等页面原生 JS，图表用 ECharts
后端路由 + 服务：取数、报告生成、专项打包、预测、检索FastAPI，SSE 流式返回
共享包 analysis/跨项目复用的核心逻辑：AI 客户端、SQL 改写/生成、知识/专项存储纯 Python，无框架依赖
数据仓库业务数据源，按产品代码换库StarRocks / MySQL
大模型SQL 生成、改写、报告撰写、归因内部 LiteLLM 网关（OpenAI 兼容）

02系统架构

请求自顶向下：前端页面发 HTTP/SSE → FastAPI 路由分发 → 服务层编排 → 共享包 analysis/ 提供 AI 与存储能力，最终触达数据仓库与 LiteLLM 网关。

04运行逻辑

4.1 一次对话请求的完整链路

用户在对话页选游戏、发问，后端按下图链路流转。取数 SQL 的来源有三：已匹配的全局 SQL（就近改写）、专项绑定的冻结 SQL、或 AI 从零生成。

4.2 专项（Skill）快照生命周期

专项是「方法说明 + 绑定 SQL/知识/预测」的自包含包。保存时把外部来源改写 / 精简后冻结进专项目录，运行直接读冻结内容，并靠指纹检测来源是否漂移。

快照面板（专项页「🧊 快照与溯源」）支持：打开查看 / 就地编辑 / AI 改写 / 删除单个快照 / 一键刷新。删除只移除冻结件与溯源记录，运行自动回退到全局源，不影响专项关联。

05关键约定

这些约定是报告产出正确性的基础，改写 / 生成 SQL 与生成报告时都必须遵守。

5.1 SQL 头部注释（决定图表形态与报告归位）

每条 SQL 顶部带结构化注释，其中 【图表】 与 【右轴】 直接决定图表类型与坐标轴（饼图只来自此标记）。

-- ============================================================
-- 【步骤名】付费国家构成
-- 【归属章节】🔍 明细下钻 ③ 国家
-- 【粒度】周
-- 【输出列】国家, 流水(CNY)
-- 【图表】饼图
-- ============================================================
with agg as ( ... )

图表类型判定优先级：用户显式指定 > SQL 头部 【图表】 标记 > 启发式（时间类 X 轴→折线，否则→柱状）。

5.2 金额与币种

  • price_cny_from_api = 人民币（CNY）；price_usd_from_api = 美金（USD）。两者不得互相替换。
  • 金额列名必须带币种后缀，如 AS "流水(CNY)"、AS "ARPU(CNY)"。
  • 默认业务口径为 CNY；目标流水与流水必须同币种才能算达成率。

5.3 时区（TZ）

  • active 视图必须按库过滤 tz；无 tz 字段的表用 dteventtime + dim_gameperiod_info.svr_timezone 转时区。
  • SQL 改写时，convert_tz / date_utc8 / china_date / dteventtime_utc8 及 {时区条件} 占位符一律原样保留。

5.4 库前缀与日期

  • 查询数据只能按产品代码换库：拳皇国服 kof、东南亚 kof_sea，跨地区要都查。
  • SQL 里的库前缀形如 pf_rooc_am.，执行时由系统按所选游戏自动替换，无需手改。
  • 日期必须写成相对时间 current_date() / now() 或 {开始日期} / {结束日期} 占位符，禁止硬编码具体日期字面量。
