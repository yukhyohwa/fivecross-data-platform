# 游戏选择器改造评估（2026-10-23）

## 需求回顾

1. 游戏选择器从顶部导航移到**聊天窗口左侧：模型下方、专项上方**；新增「不选游戏」选项。
2. 「不选游戏」：按 RBAC 鉴权，用户可获取**任何游戏**的数据；用户没说选什么游戏时，系统要**提问**。
3. 选了游戏：默认查该游戏，用户不提游戏不触发提问。
4. 选了游戏但问题指向**别的游戏**：走鉴权——通过就查；不通过不查，**追加提示建议切到对应游戏**。

## 现状盘点（已有基础，不是从零做）

| 需求点 | 现状 |
|---|---|
| 前端选择器 | 顶部导航 `nav.js`（聊天/报告/聊天历史 3 页共享），localStorage `chatbi.game` + fetch 全局注入 `X-Game` 头 |
| 聊天侧栏 | `chat.html`：模型 → 专项 → 历史，插入位置现成 |
| 鉴权 | `effective_games` / `is_game_allowed`（RBAC 游戏×身份）+ `deps.get_game` 硬拦 403，已就绪 |
| 需求 4（点名别的游戏） | **已实现**（2026-10-23）：`_resolve_game` 点名优先→有权直查+「建议切换」提示、无权留当前游戏+提示；深度分析 `resolve_cross_game` 同理；`tests/test_cross_game.py` 回归已过 |
| 提问机制 | **已存在，不需要新 MCP/skill**：普通聊天有「游戏确认卡」（game_confirm）机制；深度分析有 `ask_user` 工具（提问+可点选项卡，三前端已通） |

## 缺口（本次要做的）

### 前端（小）

- `chat.html` 侧栏插一个游戏选择 panel（模型下、专项上），加「不选游戏」项。
- 顶部导航选择器去留：报告/聊天历史页仍依赖它（产品决定，见「需要你」）。
- 「不选游戏」需要**显式哨兵**（如 `X-Game: __any__`），区分「没选过游戏」（历史默认语义）与「主动不选」——否则所有页面行为会变。

### 后端（中，风险集中在这一点）

- 「不选游戏」= `get_game` 不再回落具体游戏 → 需 optional 语义：`_handle` 全链路（chat.py 约 3000 行）里所有 `game["key"]` / `game["db"]` 的使用点要有 game=None 兜底：先解析出目标游戏（`_resolve_game` 复用）再取数/检专项/查知识库。
- 用户没提游戏 → 提问：普通聊天扩展游戏确认卡（选项 = 该用户允许的游戏列表）；深度分析直接用 ask_user（已就绪）。
- 无权限用户「不选游戏」：回落其允许集第一个游戏（维持现状语义，见「需要你」）。

### 测试（小）

- `tests/test_cross_game.py` 已有基底，补「不选游戏 + 未点名 → 提问」「不选游戏 + 点名有权 → 直查」路径。

## 风险评估

- **前端**：1 个 panel + 选项 + 哨兵值，无新机制。
- **后端**：中等——改动面是「game 可为 None」的顺序调整 + 提问语义扩展，不是新机制；越权兜底和跨游戏解析均已实现并测试过。工作量估计约 1 天（后端为主）。
- 结论：**变动不大**，可做。
