## 一、验证轮超时根因与修复

**根因**（三层叠加）：
- 报告三模型流水线 `_complete_report` 的快速档用 `READ_TIMEOUT=300s`，而实测关推理单轮最长 ~240s，网关负载抖动即贴边打穿；
- 共享预算 `_call_with_shared_budget` 一次逻辑调用只给一个 READ_TIMEOUT 预算，300s 整段被首次尝试耗尽 → **零重试**；
- 验证轮输入 = 生成轮全文报告 + 数据块（长上下文），deepseek-v4-pro 在验证场景同样慢。

**修复**：
- 报告三模型（生成/验证/汇总）快速档与深度档统一放宽读超时到 `DEEP_READ_TIMEOUT=900s`（`analysis/ai_client.py` 的 LITELLM_DEEP_READ_TIMEOUT，可部署级调整）；
- 验证轮默认档改为 **deepseek-v4-flash**（任务默认档，见下）——验证是数据复核而非长文创作，快速档足够；
- 网关真挂死的最坏情况：一次 900s 后优雅降级（验证轮失败回退生成轮结论），不再 300s 硬断。

## 二、三模型配置前端消失的原因

`frontend/nav.js` 的 ⚙️ 配置弹窗仍在，但 React 单壳（P5 前端统一）里 vanilla 页面以 iframe 嵌入，nav.js 的 `if (window.self !== window.top) return;` 判定让弹窗在 iframe 内不渲染；React 壳（Layout.tsx）从未实现该入口。**结论：功能没删，入口丢了。**

## 四、设计

### 存储与优先级

```
模型管理（data_ai/model_config.json）> 环境变量（TASK_MODEL_*/AGENT_MODEL/AGENT_FALLBACK_MODEL/SPLIT_MODEL/LITELLM_FALLBACK_MODEL）> 任务默认 > 系统默认（DEFAULT_MODEL）
```

- `backend/services/model_config.py`：槽位注册表 MODEL_SLOTS + `_resolve(key) -> (model, source)`；`read_model_config`/`write_model_config` 对非法模型名双层拦截（读时回落、写时不落盘）——防重演老 report_config.json 被写占位名 x/y/z 导致网关挂起 ~290s 的坑。
- `config.task_model(task)` 仍是全站唯一任务→模型入口（审计 P1-4），内部改走 `_resolve`：SQL/专项/知识库/算法/报告三模型/缺口修复/指标拆分**自动全部生效**，无需逐个改调用点。新增 `agent_fallback_model()`、`global_fallback_model()` 同源。
- **老 report_config.json 一次性迁移**：store 首次读取时把 model_gen/ver/sum 迁进新槽位并落盘，之后 store 为准，老文件保留作历史。`backend/services/report_config.py` 改为 store 适配器，`/api/reports/config`（vanilla 三模型弹窗仍用它）键结构不变。
- **全局兜底动态化**：`analysis/ai_client.py` 的 fallback 从常量改为可运行时切换（`set_fallback_model`）；lifespan 启动同步 + PUT 接口即时同步，进程级全局变量（与既有设计一致）。

### API

- `GET /api/admin/config/models`：13 槽位（模型/来源/覆盖值）+ 可用模型列表 + 系统默认（登录即可读）
- `PUT /api/admin/config/models` `{overrides: {槽位: 模型名|""}}`：仅系统管理员（`_require_system`）；空串=清除覆盖；非法名/未知槽位忽略
- 来源标注：模型管理/环境变量/任务默认/系统默认

### 前端

- 系统管理 → **模型管理**（`ModelManagementPage.tsx`，样式随 ProjectMappingPage 的 var(--) 惯例）：每槽位下拉（自动=显示当前生效模型+来源徽标）、行内重置、待保存标记、恢复全部默认、保存修改；banner 说明优先级与 per-user/Jev 的去向。
- `LLMConfigDialog.tsx` 旧注释（指向 SPLIT_MODEL/report_config.json）改为指向模型管理。

## 七、对抗审查加固批（2026-10-26 第二轮，finders 6-10）

审查发现 3 类实质问题，全部收口：

### 1. chat 槽位被 3 处旧链路架死（重要）

- **chat.py 解读/复核耦合**：`_handle` 里 `model_ver = report_config.read_report_config().get("model_ver")`——验证轮任务默认改成 flash 后，聊天里的 SQL 检索/复核/结果解读会**静默从 pro 降档**。已解耦：解读/复核跟随主对话槽位 `config.task_model("chat")`。
- **meta.py /api/models 默认档**：原 `config.default_model()` 直取，聊天页下拉默认展示与生效模型脱节。改为 `config.task_model("chat")`。
- **vanilla 聊天页总回传显式 model**：app.js 15 处请求都带 `model: state.model`，后端显式传参优先 → chat 槽位对聊天窗口永远不生效。改为 `state.modelExplicit` 标记：用户未改选下拉时不回传，后端按槽位解析（模型管理改动即时生效）。

### 2. store 并发与崩溃安全加固（model_config.py 重写）

- 读-改-写加 `threading.Lock`：`/api/admin/config/models` 与 `/api/reports/config` 共享 store，并发 PUT 不丢更新（新增并发写测试）；
- 写盘原子化：tmp 文件 + `os.replace`，断电/崩溃不留半截 JSON；覆盖前先备份 `.bak`；
- 进程级 mtime+size 读缓存：`task_model` 在 LLM 热路径上，文件未变不再重复磁盘 IO；
- 迁移按路径记账且**只跑一次**：store 被删/老文件被改坏都不会让脏数据复活（新增单发测试）；
- 空写不落盘：store 从未存在且无可写内容时不创建文件，保留「未迁移」状态；
- ai_client 兜底切换单次求值：`except` 分支里 fallback 只取一次，避免与 PUT 保存并发时判等/调用/记账用不同值。

### 3. 前端页与接口口径

- **.gitignore `model_config.json*`（不入库）**：部署用 `git reset --hard`，若入库，服务器 admin 保存的覆盖每次部署被覆盖丢失。老 report_config.json 保留在库（空默认模板，历史兼容）。
- reports.py `PUT /config` 写盘 OSError → 500 清晰报错（与 config_admin 同口径）。
- ModelManagementPage：自动档显示 `auto_model`（清除覆盖后回落值）；无 system 权限只读（banner+控件禁用，与 GlossaryPage 同口径）；sessionStorage 草稿持久化 + 刷新内联确认（审计 P2-5 不用 window.confirm）；保存中禁用全部控件；「恢复全部默认」只标有覆盖/非空编辑的槽位，无可重置项时提示而非全表标脏；下拉/按钮加 aria-label、消息 aria-live。
- 测试扩充：迁移单发/空写不建文件/PUT 空覆盖仍迁移/损坏 store 读空+写备份/并发写不丢更新/auto_model 字段；env 清理归一 AGENT_MODEL 等 import 期常量。
