## 直接归因

- 指定角色觉醒礼包归对应角色。
- `gift8` 限時閱覽衝刺包、`gift9` 限時閱覽豪華包归五条悟。
- 用户明确指定 `gift19` 英雄试炼礼包归五条悟，仅用于此首周窗口。
- 自选礼包通过购买订单、道具发放、开箱库存、`item_use` 选择关联；英雄胚子缺少资源内容时，使用同账号同角色唯一 `hero_add` 补充，并防止重复使用事件。
- 觉醒和天赋道具的英雄关系由真实消耗事件验证，不靠道具 ID 位数猜测。
- 免费与付费同类库存无法区分时不擅自套用先进先出。不明保留未开启、通用资源、无法唯一关联等部分。
- 一包多份同等自选内容按选择份数分配整包价值，附赠通用资源不单独估价。因此星耗归类值可能出现小数。

## 角色范围和舍入

当前表共 24 个角色：1 个 S、8 个 A、15 个 R。R 是用户定义的“既不是 S 也不是 A”，对应既有周报分类 SQL 的剩余类别 B。本表范围不是整个游戏所有上线角色清单，不自动加入后续上线角色。

金额和分配后的星耗保留两位小数；采用最大余数法补齐尾差，确保每行角色加不明等于总额、每列合计等于明细加总。未知金额不参与任何比例分母。

## 保存和复算

- `sql/`：38 个成功执行过的查询定义。
- `data/raw/`：真实原始查询结果，Git 忽略；不要更改冻结快照。
- `config/case.json`：角色、漫画、稀有度和分摊规则。
- `scripts/build_case.py --verify-reference`：从原始流水重建各版，并逐格与原交付比较。
- `scripts/verify_case.py`：核对源文件哈希、行数和结果守恒。
- `scripts/test_allocations.py`：分摊、舍入、范围控制单元测试。
- `scripts/fetch_queries.py`：默认只校验和生成任务；加 `--execute` 才复用现有客户端重新查询，新的结果独立存放，不覆盖归档。
