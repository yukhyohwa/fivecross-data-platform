# 买量数据知识库

## 1. 数据来源与延迟

买量的展示、点击、消耗数据均来自 AF（AppsFlyer）后台。数据获取本身存在延迟，最大延迟可达 **6 小时**。因此在查看或计算买量相关数据时，需注意数据可能并非实时完整，临近时间窗口的数据存在补录可能。

## 2. 时区口径

AF 后台的展示、点击、消耗数据时区默认均为 **UTC+8**。

为保持口径一致，买量相关的 KPI 指标也统一按 **UTC+8** 计算。

**SQL 编写约定：** 凡是涉及买量相关数据、且用到时区（`tz`）的场景，一律写死为 **UTC+8**，不得使用当地时区或其他时区。

> ⚠️ 注意：由于买量数据统一采用 UTC+8 时区，与业务当地时区计算出的结果会存在差异，这是预期内的口径差异，使用数据时需加以说明。

## 3. 归因流程

整体归因流程如下：

1. 先从三方（AF）获取点击的明细信息。
2. 通过 SDK 采集的 **激活时间和注册时间**，匹配用户是否命中媒体标签。
3. 命中后，在设备和账号的用户表里，根据 **新增** 和 **回流用户** 两个状态，进行媒体信息的染色。

### 3.1 国内归因顺序

国内买量归因按以下优先级依次匹配：

1. **子包归因（优先）**
2. **硬件 ID 归因**
3. **IP + UA 模糊归因**

### 3.2 海外归因顺序

海外没有子包归因，直接通过 AF 回传的点击数据进行归因：

1. **硬件 ID 归因**
2. **IP + UA 模糊归因**

## 4. 归因规则

- 归因依据 **激活（install）时间最近** 的媒体信息进行归因。
- 媒体点击信息的 **有效窗口期为 7 天**，超过 7 天的点击不参与归因。
- 归因染色区分 **新增用户** 与 **回流用户** 两个状态，命中后在设备和账号的用户表上分别进行媒体信息染色。

## 5. 再归因与数据截断

- **再归因（流失后回流）** 的窗口时间为 **30 天**。
- 发生再归因时，上一次归因产生的 **LTV 和 ROI 会进行截断**。

### 5.1 归因类型

归因分为两种类型：

| 类型 | 是否截断 LTV/ROI | 说明 |
|------|------------------|------|
| 首次归因 | 永不截断 | 用户首次激活产生的归因 |
| 再归因 | 会截断 | 存在 1~n 次再归因，每次再归因按第 n 次截断 LTV 和 ROI |

即：首次归因对应的 LTV/ROI 始终保留完整；一旦发生再归因，数据将以最近一次（第 n 次）再归因为准进行截断计算。
