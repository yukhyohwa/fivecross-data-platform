# 版本活动排期提取判定链

## 判定链范式（可推广到其他「文本→结构化」提取任务）
1. 预处理：标题去中文数字（如"第十一期"→"11期"）。
2. 实体原样保留：活动序号/名称不改写、不翻译。
3. 分类判定链：按关键词表顺序判定，命中即停（判定顺序不能打乱）。
4. 时间解析：yyyy-MM-dd HH:mm:SS；无具体时间取 05:00:00；00:00:00 修正为前一天 23:59:59；到分钟补秒。
5. 时间完整性强制：起止任一无法推断，整条丢弃（不产出半截排期）。
6. 输出格式：只输出 JSON，不带解释文字。

## class 判定关键词表
- 通用版：核心商业化 / 常规商业化。
- rooc 版顺序：休闲小游戏 → 充值加赠 → 累充 → 外观商店 → 金币商店。

## 商店上架清单
- 合并成一条活动记录（附清单），禁止每个时装/商品拆一行。

## 注意事项
- 时间修正规则是硬口径（维护后无时间取 05:00:00 等），不能按"更合理"自行改。
- 反例同样重要：判定不了的条目宁可丢弃，也不要归进错误的 class。
