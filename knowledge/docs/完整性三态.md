# 数据完整性三态与合并规则

## 适用游戏
rooc 等 RO 产品线（会话数据表 Parquet + DuckDB 加工链的通用规则）。

## 三态语义
- complete=true：完整；complete=false：不完整（如溢出时只存了部分行）；complete=null：未知。
- complete 是完整性，不是行数：行数少不等于不完整，行数多不等于完整。

## combine_complete（只降不升）
- 任一 false → false；否则任一未知 → null；全部 true 才是 true。
- 即使加工结果只有一个聚合值，也不能把不完整的输入"洗"成完整结果。

## 用法
- complete=false/null 的表只能做带覆盖范围说明的探索；回答整体指标前回源补齐。
- 旧 JSON 溢出引用没有 complete 键——不能报成"完整性未知"，如实说明无声明。

## 注意事项
- transform_tables 必须 SELECT/WITH 开头；中文列名/禁用词用双引号；DuckDB 反斜杠不转义。
- metric_notes 口径照做：人日不能叫去重人数、比率从分子分母重算、留存/LTV 按队列加权。
