# 黑子JP｜9月10日起新增设备异常与刷号判断

## 结论

**高置信度存在批量刷号。** 2026-09-10～09-12 的 NUU 上升几乎全部来自已被现有标签命中的设备，而非正常新增增长：

- 基线期（09-01～09-09）日均 NUU 110.7；异常期（09-10～09-12）日均 427.7，增加 286.4%。
- 排除现有黑名单关联设备后，日均新增反而由 85.9 降至 81.3（-5.3%）。异常期 1,283 台新增设备中，1,039 台（81.0%）曾关联现有 `cohort_20231116_224917` / `cohort_waternew` 用户。
- 以首个登录用户归类的 1,037 台异常期已知黑名单设备中，989 台（95.4%）来自泰国、1,013 台（97.7%）为 Android。前五个完整 IP 覆盖 988 台（95.3%），且设备量呈 664/108/108/72/36 的批次特征。
- 该组截至 09-13 的登录最高等级中位数与 P90 均为 1；D1 登录设备占比约 13.2%，明显低于异常期非黑名单新增设备的约 33.6%。
- D0 行为高度模板化：`task_reward` 覆盖 93.2%、`account_bind` 92.8%、`mail_get` 93.5%、`roulette_buy` 92.6%；但每参与设备仅约 1.32 条 `task_finish`、1.10 条 `battle_result`，明显少于正常基线的 5.60 与 2.68。

## 对两个原因假设的判断

### 1. 新手任务奖励调整

**有较强支持，但更准确地说是“批量跑固定新手奖励路径”。** 异常刷号组几乎统一领取任务、绑定、邮件及赛季奖励。D0 有 964 台设备通过 `task_reward` 获得资源 ID `10000002`（合计 387,900）及钻石 `10000003`（合计 31,320）。这与“新手奖励调整后被脚本化领取”一致。

当前仅凭日志没有道具名称维表，报告保留资源 ID，不把 `10000002` 擅自命名为具体球员养成材料；若要确认是否正是奇迹1&2代养成道具，需要再用策划配置表映射奖励包/道具 ID。

### 2. 为火神4代上线提前囤钻

**现有证据不支持。** 异常刷号组 D0-D1 钻石末次余额中位数 40、P90 140，明显低于正常基线的 160、1,106；人均钻石获得 339.19、消耗 436.04，净流向不是囤积。D0 有 947 台设备在 `shop_buy` 消耗钻石 382,810；`roulette_buy` 覆盖虽高，但 `gacha_spring` 仅覆盖 1.7%，更像固定新手/兑换流程，不像为未来卡池长期囤钻。

## 数据范围与口径

- 产品：黑子的篮球 JP；TA App 9；事件表 `ta.v_event_9`。
- 完整观察日截止：2026-09-13；新增 cohort 截止 2026-09-12，保证 D1 为完整自然日。
- NUU：设备自 2023-11-15 起首次 `login` 的自然日，设备粒度 `#device_id`。
- 留存：注册日后第 1 个自然日再次 `login` 的设备数 / cohort 新增设备数。
- IP：首次登录事件的 `#ip`；地理位置取同一事件的 `#country/#province/#city`。
- 黑名单：`user_result_cluster_9` 中 `cohort_20231116_224917`、`cohort_waternew`。
- 行为：设备首个登录用户 `#user_id` 在 D0-D1 的事件；这是设备 cohort 的首用户归因，不等于跨账号永久设备归属。
- 钻石：`a_rst` 中资源 ID `10000003`；JP 数组字段顺序沿用库内已验证写法 `diff,key,after,before,id`。
