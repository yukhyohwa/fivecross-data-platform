# 校验清单

## 取数前

- [ ] 日期使用 Asia/Shanghai 分区日，且包含策略变更前后完整窗口。
- [ ] 排位主分析限定 `model_type=2`；漫斗赛仅在等待时长 SQL 中使用 `model_type=5`。
- [ ] `team_member_num` 已确认 1/2/3 分别是单/双/三排。
- [ ] 段位方向与 RankLevel 映射仍有效。
- [ ] 内部号、水号黑名单可访问。

## 数据质量

- [ ] 00 号 SQL 的组队关联覆盖率、段位覆盖率达到可接受水平。
- [ ] 依赖阵营的分析仅保留恰有两个 `rank` 的对局。
- [ ] 单局玩家数、缺失 side、异常 queue size 无突变。
- [ ] `match_cost` 非负；缺失率和极端值单独报告。
- [ ] 英雄杯可解析率和双方已观察人数无明显异常。

## 指标一致性

- [ ] 单排对手三类互斥，数量之和等于单排玩家-对局分母。
- [ ] 胜率、Bot 率、超时比例均在 0–1。
- [ ] 严格不均衡对局数不超过真人对局数。
- [ ] 双排筛查漏斗单调递减。
- [ ] Raw、标准化、去重 battle Bot 率清楚标注不同分母。
- [ ] 双排对双排会产生两个阵营视角，未误当成重复数据。

## 解读

- [ ] 不把相关性写成匹配策略导致的因果。
- [ ] 不把 `score` 当排位积分。
- [ ] 不把风险复核名单写成作弊名单。
- [ ] 星耀 21 与 22+ 分开，并核查三排例外的 `match_cost>=999` 与缺失样本。
- [ ] 等待时间只代表成功结算对局，不声称覆盖未成局超时。
