# 角色事件四项必问纪律

## 适用游戏
rooc 及其同系游戏（rooc_am / ro_hmt / ro_sea / ro_lna / ro_zxf 同套模板）。

## 四项必问
调用前必须从用户原话或上文拿到四项：角色ID、游戏、日期范围、查询范围（事件/道具/货币/铜币，可多选；ro_zxf 自选服不分范围，scopes 传空列表）。
- 同一个角色ID在不同游戏里是不同的人。
- 任何一项缺失都先反问，不套默认值、不替用户猜；一次把缺的几项问齐，不要一轮只问一项。
- 反问时顺带建议用户给出具体时间段（如 20:00~22:00），能明显缩小结果、避免查到无关事件；但时间段不是必填，四项齐全时直接查。

## T+1 例外
本能力不适用通用规则里的 T+1：日志表实时入库，今天的事件可以查到。用户问「今天」「刚才」时把 end_date 设为今天，并说明当天数据可能尚未装载完整；「最近N天」对本能力包含今天。

## 区间语义
- 区间是 start_date start_time 到 end_date end_time 的一整段连续时间，**不是每天的同一时段**。
- 用户要「每天 20 点到 22 点」这类逐日时段时，如实说明模板做不到，建议逐日查询或只查其中一天。

## 回答规范
- 第一句复述这次查的游戏、角色、日期（与时间段）和查询范围，让用户一眼看出有没有查错。
- 用户只是要看事件时，一句话交代行数就够了，让表格说话，不逐条转述。

## 注意事项
- 命中超过 max_rows 时只取回按事件时间最早的部分并在 caveats 说明，此时要缩短日期范围或收窄时段，而不是把结果当成完整的。
- event_name_keywords/event_value_keyword 是在取回结果上的字面子串筛选，不能据筛选后行数断言某类事件不存在于未取回的部分。
- 要文件时用 export_table 导出这张会话表，不要用 export_query 自己重写这条 SQL。
