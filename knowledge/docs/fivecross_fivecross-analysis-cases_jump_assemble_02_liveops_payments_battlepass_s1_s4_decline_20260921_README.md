# JUMP Assemble TC｜S1–S4 BP 販售下滑分析

## 決策問題

本 case 分析 S4 Battle Pass（BP）販售表現，回答「BP 為何越賣越差」，並為後續 BP 商品與獎勵調整提供依據。

1. 對比 S1–S4 BP 販售、滲透、購買節奏與完成度。
2. 分析 BP 買家選擇精英版與進階版／豪華版的比例及人群差異。
3. 分析 BP 買家的特供角色持有與覺醒養成，檢查 S2–S4 以特供角色自選與覺醒為主的獎勵是否仍有需求。
4. 分析 BP 產出道具的流入、消耗與期末存量，判斷是否存在供給過剩或邊際價值下降。

## 初始口徑

- 資料源：ThinkingData / Trino，`ta.v_event_23`。
- BP 領獎：`battlepass_reward`。
- BP 付費版本：`battlepass_advance`。既有 `indexid=1/2` 與小卡／大卡的對應仍待商品設定驗證；S4 稽核顯示兩種 indexid 購買模式皆可領到 item 7084093，故本次不把 indexid 直接當成商品檔位結論。
- 獎勵重疊：大卡買家會同時領取精英軌與進階軌獎勵，所以版本是互斥買家分類，道具產出則按實際領取記錄，不把兩軌誤當成互斥。
- 里程碑：大卡 10、50 級為角色自選箱；70 級後大小卡可取得另一個隨機漫迷精華箱。S4 D1–D5 僅 1 名玩家達 70，70+ 尚不作早期原因判斷。
- BP 等級：展開 `bplevel` 後取每位玩家每期最大值。
- 玩家 ID：優先使用 `COALESCE(fc_sdk_common.lcx_id, sdkcommon.lcx_id, "#account_id")`。
- 排除：`internal_users`、`is_water`、`is_water_mod`、`suspicious_ip`。
- 角色養成：每位玩家、每個角色在觀察截止日的最新 `daily_role_card_snapshot`；覺醒數為 `CARDINALITY(card_awake)`。
- 所有因果敘述先視為假設。跨期差異可能同時受 DAU、玩家生命週期、同期卡池、定價、獎勵內容與曝光影響。

## 交付物

- `sql/`：事件探索、跨期成效、版本結構、角色選擇與養成、道具流量與存量、資料品質查詢。
- `inputs/raw/`：查詢原始結果。
- `scripts/`：查詢、彙總、Excel 與 PPT 生成腳本。
- `outputs/`：分析工作簿和資料圖表型簡報。

## 本次結論摘要

- S4 D1–D5 付費買家 705 人，較 S3 的 840 人下降 16.1%；同期活躍用戶下降 10.9%，付費滲透率由 1.25% 降至 1.17%。
- S4 首日新增買家 490 人，略高於 S3 的 482 人；但 D2–D5 合計只新增 215 人，較 S3 的 358 人下降 39.9%。
- 新 BP 買家由 S3 的 88 人降至 S4 的 44 人，減半；歷史 BP 買家只下降 12.1%。新客補充不足是最大額外缺口。
- 既有 indexid 分組占比相近，但因 indexid 與商品檔位映射尚待驗證，暫不以「版本降檔」作為結論。
- S4 已直接確認 BP 角色箱 item 7084093：BP 領獎取得箱子後，同帳號同一秒出現 `resource_change nums=-1`（`reason=使用自选礼包道具`）與 `hero_add`。D1–D5 共領取 692 個箱、104 名玩家直接開箱，直接使用率 15.0%。S1–S3 尚未逐期確認箱體 ID，原「5 分鐘 hero_add」代理不再作跨期開箱率或需求強弱結論。
