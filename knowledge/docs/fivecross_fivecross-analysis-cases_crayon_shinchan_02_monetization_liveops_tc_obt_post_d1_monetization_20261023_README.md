# 小新繁中 OBT 首日後付費與商品活動消費

分析 2026 年 10 月 14 日至 22 日的收入來源，以及中小 R 在創角首日後仍購買的商品、活動和價格區間。現金直購與晶鑽最終去向合併觀察，購買晶鑽本身不當作最終商品需求。

## 分析口徑

- 資料源為 App18 `ta.v_event_18`、商品維表及有效訂單每日匯率。玩家按 `fc_id` 合併角色，創角日取觀察期間首次 `new_role` 日期。
- 「首日後」是創角翌日起的所有購買，買一次也納入，不要求與首日購買相同商品，也不要求跨日重複購買。
- 收入、晶鑽消耗及獨立晶鑽控制查詢，均按 `fc_id` 排除 `internal_users_new`、`is_water_new`、`is_windows_new`。晶鑽涉及內部用戶的排除在取數階段完成，不是最後展示才過濾。
- 現金充值排除沙盒、免費購買及 COIN 通路；USD 採訂單原始換算金額。NT$ 為有效 TWD 訂單推算的當日匯率等值，不能用固定匯率替換 USD 欄。
- 累積分 R 含購買晶鑽的真實充值，不把晶鑽消耗再次算入充值。R0=0；R1=(0,10]；R2=(10,50]；R3=(50,100]；R4=(100,300]；R5>300 美元。中小 R 主表取 R1–R4。
- 晶鑽道具 ID 為 10206，原始扣款除以 100 後與台幣 1:1。最終商品活動消費＝現金商品 NT$＋晶鑽最終消費 NT$；這是消費需求口徑，不是當日新現金收入。
- 純儲值／換幣商品 ID 為 101301–101307、101401–101407、136001–136009、137001–137009。從商品活動偏好排除，收入及分 R 仍保留真實充值；每日另列晶鑽換幣排除額以供勾稽。
- 同 SKU 的現金與晶鑽購買合併，購買人數按帳號去重，不能相加兩路徑人數。價格區間按單筆訂單或扣款，不把連抽單次扣款視為整場活動預算。
- 補充的嚴格跨日復購：排除創角日後，同一 SKU／活動在至少兩個不同日期購買；合併現金與晶鑽日期聯集。同日多次不算跨日。

## 晶鑽最終去向歸因

先以 `item_change` 中 10206 的 before>after 取得每筆扣款，再匹配同帳號、同角色、同日，扣款後兩秒內的商城購買、普通伙伴／技能抽卡、限時伙伴／坐騎獎勵事件。同商品／活動的多條獎勵先合併，只有唯一目的地才歸因；零候選與多個不同候選分別留作未匹配與多候選未歸因。每筆扣款只計一次，不強行分攤給熱門活動。

每日晶鑽扣款與另一條獨立 `item_change` 彙總 SQL 勾稽。全期首日後約 15% 晶鑽未能唯一歸因，保留於總額；已識別商品排行不代表所有晶鑽需求。

## 前後對照與結論邊界

固定 7,300 名 10/14 創角且 10/15、16、19、20 均活躍玩家，比較 10/15–16 與 10/19–20，各兩天。最終消費 NT$2,130,888→655,399，減少 69.2%。缺口 50.6% 來自限時坐騎與伙伴，五類指定商品中權益卡占 18.9%、新人商品 13.9%、基金 7.5%、戰令 2.0%、開服商品 1.3%。這定位消費縮減的去向，不能單憑此判定玩家已抽滿、不想養成或活動吸引力變弱。

固定玩家只能控制活躍成員變化，未控制在線時長與活動日程。較晚創角者可觀察天數較短，不能把其跨日復購率直接視為同生命週期轉化率。多角色合併後的同 SKU 復購也不一定是同角色補貨。

## 腳本與復跑

| 檔案 | 職責 |
| --- | --- |
| config.json | 固定觀察期及本機 fivecross-data-client 路徑，不存憑證 |
| prepare.py、sql/templates/ | 從 case 內模板生成五條取數 SQL，無其他報告專案依賴 |
| fetch.py | 透過現有 data client 串行唯讀查詢，核對新檔、筆數、回傳碼及雜湊 |
| analyze.py | 原始資料整理、分 R、分類、每日與購買彙總，呼叫以下三個分析模組 |
| merged_consumption.py | 現金與晶鑽同 SKU 合併、價格區間、每日三路徑、結論文件 |
| final_destination_diagnosis.py | 固定活躍 cohort 前後消費變化及表旁結論 |
| post_d1_purchase_view.py | 中小 R 首日後所有購買主表，嚴格復購僅補充 |
| product_groups.py | 指定商品 ID 的五組映射 |
| workbook.mjs | 以 artifact-tool 生成有公式及原生趨勢圖的 Excel |
| validate.py | 原始來源勾稽、商品分類、帳號去重、Excel 34,001 個儲存格與圖表核對 |

Python 需 pandas、numpy、openpyxl（只用於讀取核驗）；可使用 `fivecross-data-client/venv/Scripts/python.exe`。Node 需共享 `@oai/artifact-tool`，本專案 `node_modules` 可建 Windows junction 指向 Codex 共享依賴，不將依賴本體放入 Git。

只重建本版 Excel：在本資料夾執行 `node workbook.mjs`。輸入 JSON 已隨 case 保留，不需重新取數。

完整刷新順序：`python prepare.py` → `python fetch.py` → `python analyze.py` → `node workbook.mjs` → `python validate.py`。取數憑證沿用外部 data client，勿加入本 case。原始玩家資料將寫入忽略提交的 `data/raw/`；本次整理沒有複製臨時專案的原始玩家資料，第一次完整刷新需先執行 fetch。

本 case 是固定日期分析。若改觀察期，除 config 外還需核對 SQL 模板、固定 cohort 比較日期、分析標題及輸出名稱，不能只修改 end 就假定所有比較自動延長。`build/` 為重建時產生的中間檔、預覽與執行核驗，不隨 Git 保存。

原臨時專案保留不動。此處不納入歷史 Excel、獨立舊診斷腳本、node_modules、快取、原始玩家明細與 debug 日誌。
